# work-record-reader — 工作记录系统

## 概述

让 opencode 拥有**外挂大脑**：每次对话自动读取工作记录，结束时自动保存。配合定时备份和归档，实现项目进度的无缝衔接。

### 核心能力

| 能力 | 触发方式 | 效果 |
|------|----------|------|
| **自动读取** | 对话开始时自动运行 | 读取最新工作记录，恢复上下文 |
| **手动记录** | 用户说"记录一下"/"保存"/"结束了" | 按规范格式写入工作记录 |
| **自动备份** | 定时任务每小时运行 | 创建 save_YYYY-MM-DD_HH:00.md 快照 |
| **月度归档** | 定时任务每月1日 | 归档到 YYYY-MM/ 文件夹 |
| **年度归档** | 定时任务每月1日 | 归档到 YYYY/ 文件夹 |

---

## 工作原理

### 自动读取流程（每次对话）

```
用户发送消息
    │
    ▼
系统提示词中有指令：
"每次对话开始时，先读取 work_records/ 最新 .md 文件"
    │
    ▼
AI 用 Read 工具读取 work_records/ 目录
    │
    ▼
找到最新 .md 文件，读取内容
    │
    ▼
AI 了解之前进展 → 回复用户
```

这是通过 `opencode.jsonc` 的 `mode.build.prompt` 实现的：

```jsonc
{
  "mode": {
    "build": {
      "prompt": "你是我的AI编程助手。工作目录是 F:/opencodework/。每次对话开始时，先读取 F:/opencodework/work_records/ 最新 .md 文件，了解之前做了什么，然后再回复用户。"
    }
  }
}
```

### 运行时行为

当技能被系统调用时，AI 自动执行：
1. **读取目录**：`read("F:/opencodework/work_records/")`
2. **找最新文件**：按修改时间排序，取最新的 `.md` 文件
3. **读取内容**：用 Read 工具读取文件全部内容
4. **上下文恢复**：在回复中体现已读取的记录

## 工作记录规范

### 目录结构

```
F:\opencodework\work_records\
├── 2026-05-12_工作记录.md          ← 正式工作记录文件
├── save_2026-05-12_14-00.md        ← 每小时自动备份
├── YYYY-MM/                         ← 月度归档文件夹
│   └── 2026-05-12_工作记录.md
└── YYYY/                            ← 年度归档文件夹
    └── 05/
        └── 2026-05-12_工作记录.md
```

### 文件命名规则

| 类型 | 格式 | 示例 |
|------|------|------|
| 正式记录 | `YYYY-MM-DD_主要内容概括.md` | `2026-05-12_API接口重构.md` |
| 备份快照 | `save_YYYY-MM-DD_HH-00.md` | `save_2026-05-12_14-00.md` |
| 月度归档 | `YYYY-MM/文件名` | `2026-05/2026-05-12_API接口重构.md` |
| 年度归档 | `YYYY/MM/文件名` | `2026/05/2026-05-12_API接口重构.md` |

> ⚠️ **关键规则**：`主要内容概括` 必须是对当天工作的真实总结（如"技能重写与脚本落地"），不准用固定的"工作记录"作为概括。

### 正式记录格式

```markdown
# YYYY-MM-DD 工作记录

## 项目时间
- 开始时间：YYYY-MM-DD HH:MM
- 结束时间：YYYY-MM-DD HH:MM

## 工作内容

### 1. 项目名称
- 完成时间：YYYY-MM-DD HH:MM
- 关键内容说明
- 技术要点/踩坑记录

### 2. 项目名称
- ...

## 未完成工作
- [ ] 待办事项1 — 描述
- [ ] 待办事项2 — 描述
```

### 跨天规则（00:00-00:59 时段）

- 定时任务继续每小时创建备份，不受日期变更影响
- 用户说"结束"时，根据备份时间判断归属日期
- 启动时自动检测跨天状态并提示

## 操作流程

### AI 主动记录

当用户说以下触发词时，AI 应自动写入工作记录：

| 触发词 | 行为 |
|--------|------|
| "记录一下"/"保存进度" | 写入当前进展到最新工作记录文件 |
| "结束了"/"保存工作" | 合并备份，生成正式文件（文件名须包含内容概括），清理临时备份 |
| "今天做了什么" | 读取今天的工作记录并总结 |

### 写入内容规范

AI 写入工作记录时应包含：
- ✅ 完成的事项及时间
- ✅ 技术决策和原因
- ✅ 遇到的问题和解决方案
- ✅ 未完成工作/待办（格式：[ ] 事项 — 描述）
- ❌ 密码、API Key 等敏感信息

## 每日提醒规则（重要）

每次对话开始时，AI 读取工作记录后**必须执行**：

```
1. 检查最新工作记录中是否有 "## 未完成工作" 板块
2. 如果有未完成的 [ ] 事项
   → 在回复开头提醒用户："提醒：上次有未完成的工作——xxx"
3. 如果事项已完成但记录未更新
   → 询问用户是否已做完，标记为 [x]
4. 如果所有事项都已完成
   → 无需特别提醒
```

## 配套脚本

位于 `F:/opencodework/work_records/` 目录下：

| 脚本 | 作用 | 触发方式 |
|------|------|----------|
| `hourly_backup.py` | 每小时备份当前工作记录 | Windows 定时任务 |
| `archive.py` | 月度/年度归档 | Windows 定时任务 |
| `work_record_helper.py` | 检查工作记录状态，处理跨天逻辑 | 手动或启动时调用 |

### 定时任务配置

| 任务名 | 触发时间 | 执行脚本 |
|--------|----------|----------|
| OpenCodeHourlySave | 每小时 | `hourly_backup.py` |
| OpenCodeMonthlyArchive | 每月1日 00:05 | `archive.py --monthly` |
| OpenCodeYearlyArchive | 每月1日 00:10 | `archive.py --yearly` |

## 与相关组件的关系

| 组件 | 关系 |
|------|------|
| **AGENTS.md** | 包含工作记录系统的完整配置规则和格式规范 |
| **opencode.jsonc** | `mode.build.prompt` 注入读取指令 |
| **opencode-memory** | work-record-reader 负责**项目进度**，opencode-memory 负责**知识沉淀** |
| **定时任务** | 实现自动备份和归档 |

> work-record-reader 和 opencode-memory 是互补关系：
> - work-record-reader = 项目日志（每天做了什么）
> - opencode-memory = 知识库（技术方案、决策理由、踩坑记录）

## 故障排除

### 技能加载失败（PowerShell 报错）
- **原因**：旧版技能尝试调用 PowerShell，但环境不支持
- **解决**：新版技能已移除 PowerShell 依赖，改用 Read 工具直接读取文件

### 读取到空文件或不存在
- **原因**：目录不存在或尚未创建工作记录
- **解决**：AI 应提示用户初始化工作记录，或自动创建第一个文件

### 跨天合并冲突
- **原因**：启动时发现备份和正式文件内容不一致
- **解决**：AI 自动合并差异，保持数据不丢失

## 适用场景

1. **项目迭代**：跨会话继续之前的工作
2. **Bug 追踪**：记录问题原因和修复方案
3. **知识积累**：沉淀技术方案和踩坑记录
4. **团队协作**：其他人接手时快速了解进度
5. **长周期开发**：几天/几周的项目保持上下文连贯
