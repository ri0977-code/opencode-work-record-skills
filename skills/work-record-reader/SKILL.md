# work-record-reader — 工作记录系统

## 概述

让 opencode 拥有**外挂大脑**：每次对话自动读取工作记录，结束时自动保存。配合归档，实现项目进度的无缝衔接。

### 核心能力

| 能力 | 触发方式 | 效果 |
|------|----------|------|
| **自动读取** | 对话开始时自动运行 | 读取最新工作记录，恢复上下文 |
| **实时写入** | AI 每完成一件事自动记录 | 文件始终是最新状态 |
| **手动保存** | 用户说"保存"/"记录一下" | 写入当前重要总结 |
| **结束归档** | 用户说"结束了" | 写最终总结 + 改名归档 |

---

## 工作原理

### 文件机制（2026-05-14 新版简化）

**核心规则：文件名始终带内容概括**

```
会话进行中 → YYYY-MM-DD.md（纯日期，内容不断追加）
一天结束时 → 改名为 YYYY-MM-DD_内容.md（带概括的归档文件）
```

### 自动读取流程（每次对话）

```
┌─ 系统提示词注入指令 ─────────────────────────┐
│ "每次对话开始时，读取 work_records/ 最新的    │
│  YYYY-MM-DD*.md 文件"                        │
└──────────────────────────────────────────────┘
       │
       ▼
  AI 用 Read 工具读取 work_records/ 目录
       │
       ▼
  找到最新当天 .md 文件，读取内容
       │
       ▼
  AI 了解之前进展 → 回复用户
```

通过 `opencode.jsonc` 的 `mode.build.prompt` 实现。

## 工作记录规范

### 目录结构

```
F:\opencodework\work_records\
├── YYYY-MM-DD.md             ← 会话进行中（活文件）
├── YYYY-MM-DD_内容.md        ← 一天结束后的归档
├── YYYY-MM/                   ← 月度归档文件夹
├── YYYY/                      ← 年度归档文件夹
```

### 文件命名规则

| 类型 | 格式 | 示例 |
|------|------|------|
| 工作记录 | `YYYY-MM-DD_内容概括.md` | `2026-05-14_环境优化与工作记录简化.md` |

### 记录格式

```markdown
# YYYY-MM-DD 工作记录

## 项目时间
- 开始时间：YYYY-MM-DD HH:MM
- 结束时间：YYYY-MM-DD HH:MM

## 工作内容

### 1. 项目名称
- 完成时间：YYYY-MM-DD HH:MM
- 关键内容说明
- 技术要点/踩坑记录
```

## AI 行为规则

### 实时写入（每次回复前执行）
每次回复用户前，检查本次对话是否有可记录的内容：
- 完成了某项任务 → 写入 `YYYY-MM-DD.md`
- 做了重要决策 → 写入并说明原因
- 遇到问题并解决 → 写入问题和方案
- 无明显进展 → 跳过，不写空记录

### 主动保存（用户触发）
| 触发词 | 行为 |
|--------|------|
| "记录一下"/"保存" | 写入当前重要总结到 `YYYY-MM-DD.md` |
| "结束了" | 写最终总结，改名 `YYYY-MM-DD_内容.md` |
| "今天做了什么" | 读取当天记录并总结 |

### 写入内容规范
- ✅ 完成的事项及时间
- ✅ 技术决策和原因
- ✅ 遇到的问题和解决方案
- ✅ 未完成工作/待办
- ❌ 密码、API Key 等敏感信息

## 搭配组件

| 组件 | 关系 |
|------|------|
| **AGENTS.md** | 包含完整的工作记录规则 |
| **opencode.jsonc** | `mode.build.prompt` 注入读取指令 |
| **opencode-memory** | 本组件负责**项目日志**，opencode-memory 负责**知识沉淀** |

> work-record-reader 和 opencode-memory 是互补关系：
> - work-record-reader = 每天做了什么
> - opencode-memory = 知识库（技术方案、决策理由）
